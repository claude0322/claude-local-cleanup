# 恢复与中断

计划绑定当前用户、系统、脚本版本、目标路径与内容摘要。计划保存后文件新增、修改或删除都会使原计划失效。摘要用于防止误操作和过期确认，不是抵御已控制本机账号的数字签名。

## 恢复批次

- `receipt.json`：原计划、每项状态、映射和摘要，不包含配置值。
- `NNN.original`：JSON 原文或被处理的数据。
- `NNN.original.edited`：JSON 编辑后的预期内容，用于识别中断状态。

macOS 将目标移入私有恢复目录，JSON 另存原文并校验。Windows 将目标复制到设置了当前用户 / SYSTEM ACL 的目录，确认内容一致后移除原目标；新副本继承受限 ACL。JSON 恢复可还原原始文字与缩进，文件权限可能保持更严格的设置。

Windows 复制和删除不是整体原子事务。删除中遇到锁定等错误可能留下部分原目录和完整副本，记录为 `partial`，不能当作完成。

## 操作

正常退出 Claude 与相关 Node.js 进程，使用实际记录路径：

```bash
python3 scripts/cleanup.py verify /完整路径/receipt.json
python3 scripts/cleanup.py restore /完整路径/receipt.json
```

Windows 用 `py -3`；空格路径加引号。确认恢复清单后输入 `RESTORE <前12位计划编号>`。

`verify` 的 `restore` 表示已清理且副本完整，可以恢复；`already-original` 表示原始内容仍在原处，可能未处理或已恢复。它不检查浏览器、钥匙串或服务端状态，也不保证重启后缓存不会再生成。

## 冲突和意外中断

1. 保留整个批次与原位置现有内容；不重复执行同一已用计划。
2. 按 receipt 与文件摘要核对已完成项。源数据出现新内容或副本损坏时拒绝覆盖。
3. 恢复冲突先将新资料备份到另一私有目录，再人工比较。仅在用户确认取舍后腾出原路径，不为通过检查直接删除新数据。
4. 强制结束可能留下 `~/.claude-local-cleanup/operation.lock`。确认没有操作进程后移除此锁，保留恢复目录。
5. 本工具无法恢复浏览器原生删除、独立退出登录、钥匙串删除或服务端凭据撤销。

脚本不提供永久删除副本功能。手动删除时先确认不再需要恢复，仅处理对应批次，不清空整个回收站。副本可能保存旧凭据；删除文件不等于 SSD 物理安全擦除。
