# 恢复与中断

计划绑定当前用户、系统、脚本版本、目标路径与内容摘要。计划保存后文件新增、修改或删除都会使原计划失效。摘要用于防止误操作和过期确认，不是抵御已控制本机账号的数字签名。

## 恢复批次

- `receipt.json`：原计划、每项状态、映射和摘要，不包含配置值。
- `NNN.original`：JSON 原文或被处理的数据。
- `NNN.original.edited`：JSON 编辑后的预期内容，用于识别中断状态。
- `NNN.original.before-edit`：JSON 更新时移入恢复目录的实际原文件，保留其文件身份。
- `NNN.original.before-restore`：JSON 恢复时保留的恢复前文件。

macOS 与 Windows 均使用同一文件系统内的独占移动：目标已存在时由操作系统拒绝覆盖。macOS 清除工具创建文件和恢复资料的 ACL，并设为私有权限；Windows 对恢复目录及移入资料逐项设置当前用户 / SYSTEM 的受保护 ACL。权限失败时停止并保留资料。JSON 恢复可还原原始文字与缩进，文件权限保持更严格的设置。

JSON 修改先留存独立原文副本，再将实际原文件移到 `before-edit` 或 `before-restore`，核验内容后只向空缺的原路径写入。原路径被其他程序重新创建时不覆盖；检测到保留文件继续变化时停止。一次完整清理仍不是整体原子事务，中断可能暂时留下缺失的原路径，记录为 `partial` / `restore-partial`，不能当作完成。

正常退出客户端仍是必要前提。持有旧文件句柄的进程可能在检查结束后继续写入保留版本；因此这些版本不自动删除，恢复前会再次检查，发现变化需人工比较。不能把快照检查或本工具的 operation.lock 当作对所有其他进程的持续互斥。

## 操作

正常退出 Claude 与相关 Node.js 进程，使用实际记录路径：

```bash
python3 scripts/cleanup.py verify /完整路径/receipt.json
python3 scripts/cleanup.py restore /完整路径/receipt.json
```

Windows 用 `py -3`；空格路径加引号。确认恢复清单后输入 `RESTORE <前12位计划编号>`。

`verify` 的 `restore` 表示副本完整且当前状态允许恢复；`restore-missing` 表示 JSON 事务中断导致原路径缺失，但经校验的保留版本与副本允许恢复；`already-original` 表示原始内容仍在原处，可能未处理或已恢复。它不检查浏览器、钥匙串或服务端状态，也不保证重启后缓存不会再生成。

1.0.1 可恢复 1.0.0 的合法恢复记录；执行旧清理计划前须用新版重新生成。旧版本产生的副本在恢复前会重新限制权限。

## 冲突和意外中断

1. 保留整个批次与原位置现有内容；不重复执行同一已用计划。
2. 按 receipt 与文件摘要核对已完成项。源数据出现新内容或副本损坏时拒绝覆盖。
3. 恢复冲突先将新资料备份到另一私有目录，再人工比较。仅在用户确认取舍后腾出原路径，不为通过检查直接删除新数据。
4. 强制结束可能留下 `~/.claude-local-cleanup/operation.lock`。确认没有操作进程后移除此锁，保留恢复目录。
5. 本工具无法恢复浏览器原生删除、独立退出登录、钥匙串删除或服务端凭据撤销。

脚本不提供永久删除副本功能。手动删除时先确认不再需要恢复，仅处理对应批次，不清空整个回收站。副本可能保存旧凭据；删除文件不等于 SSD 物理安全擦除。
