# 浏览器配置与网站数据

`browser_inventory.py` 只列当前用户的已知配置路径，不打开 Cookie 或密码数据库，不执行删除。自定义配置可能未列出；`unreadable-or-unsupported` 不能当作“没有数据”。

盘点会读取 Chromium 的 `Local State` 和 Firefox 的 `profiles.ini` 元数据。`Local State` 可能含账号邮箱等信息；脚本仅使用 Profile 名称，不输出账号邮箱，也不上传这些数据。

## 逐个配置处理

Chrome / Edge / Brave 的 Profile 是独立配置；网页内切换账号不等于切换 Profile。先把盘点路径与配置菜单对应。Firefox 核对配置管理页，Safari 核对个人资料。

展示要处理的配置、域名与影响，说明原生设置删除通常不能自动恢复。用户确认后：

1. 打开当前配置的网站数据设置。Chrome / Edge 通常位于隐私或网站权限，Firefox 位于隐私与安全，Safari 位于设置 → 隐私 → 管理网站数据；以当前界面为准。
2. 分别搜索 `claude.ai`、`claude.com`、`anthropic.com`，核对实际域名。
3. 只接受域名本身或以 `.` 加该域名结尾的子域。`notclaude.ai.example.org`、`upclaude.com` 或名称含 Claude 的第三方站点不属于此范围。
4. 删除获批站点项，不清空全部网站数据，不删除 Google、Cloudflare、邮箱域名或所有登录凭据。
5. 留在设置中重新检查，记录处理域名与剩余数据。不立即访问目标网站，以免重新生成数据。
6. 对下一配置重复处理；受管理、不可访问、未核验的配置单独报告。

扩展另行核实名称、发布者和 ID，并纳入确认清单。不模糊匹配删除，不修改同步、Secure Preferences 或组织策略。

## 核验

客户端操作成功、浏览器盘点成功、浏览器数据已删除是不同结果。逐配置报告：

| 浏览器 / 配置 | 具体域名 | 结果 | 依据 / 未完成项 |
| --- | --- | --- | --- |
| 实际配置 | 获批域名 | 已删除 / 无数据 / 受阻 / 未核验 | 当前设置界面核验 |

本版本不直接改写浏览器数据库。原生设置仍有残留时保留待办，不删除整库，不宣称所有痕迹永久消失。
